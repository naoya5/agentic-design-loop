## Phase 1: フロントエンドデザイン評価

4つの基準でそれぞれ 1-10 で採点する。平均スコアが閾値（デフォルト 7.0）以上で合格。

### 1. デザインの質 (designQuality)

**何を見るか**: 全体として統一感のある印象を与えるか。

| スコア | 基準 |
|--------|------|
| 9-10 | プロのデザイナーが手がけたと一目でわかるレベル。独自のビジュアルアイデンティティが確立 |
| 7-8 | プロダクションに出せるレベル。色・タイポグラフィ・レイアウトが調和 |
| 5-6 | 部分的には良いが、全体の統一感に欠ける。改善の余地が明確 |
| 3-4 | 素人感がある。色やフォントの選択がちぐはぐ |
| 1-2 | デザインと呼べるレベルではない |

**チェックポイント:**
- カラーパレットは統一されているか
- フォントの組み合わせは調和しているか
- レイアウトにリズムと余白の美しさがあるか
- 画像/アイコンのスタイルは統一されているか

### 2. 独創性 (originality)

**何を見るか**: カスタム設計か、テンプレートの焼き直しか。

| スコア | 基準 |
|--------|------|
| 9-10 | 明確な独自コンセプトがある。見た瞬間に他と違うとわかる |
| 7-8 | 独自の選択が複数見られる。テンプレートベースではない |
| 5-6 | 部分的に独自性があるが、大半は典型的なパターン |
| 3-4 | ほぼテンプレートのデフォルト。Bootstrap/Tailwind のデフォルトそのまま |
| 1-2 | 完全にデフォルト設定。何もカスタマイズされていない |

**即不合格パターン (4点以下確定):**
- 白背景にグレー/ブルーのグラデーション（AIが生成しがちなパターン）
- 変更されていない既存UIコンポーネントの羅列
- Lorem ipsum がそのまま残っている
- デフォルトの角丸・影・色をそのまま使用

### 3. 技術面 (technical)

**何を見るか**: フロントエンド実装の技術的品質。

| スコア | 基準 |
|--------|------|
| 9-10 | 完璧な実装。アクセシビリティ、レスポンシブ、パフォーマンスすべて考慮 |
| 7-8 | 技術的に堅実。主要なベストプラクティスを遵守 |
| 5-6 | 基本は押さえているが、細部にミスがある |
| 3-4 | 基本的な技術ミスが複数ある |
| 1-2 | 技術的に破綻している |

**チェックポイント:**
- **タイポグラフィ階層**: h1 > h2 > h3 > body の視覚的な区別が明確か
- **スペーシング**: margin/padding の一貫性。8px グリッドなどのシステムがあるか
- **色の調和**: コントラスト比 (WCAG AA: 4.5:1 以上)。アクセント色の使い方
- **レスポンシブ**: ビューポート幅の変化に対応しているか
- **フォント**: ウェイト・サイズの使い分けが適切か

### 4. 機能性 / UX (functionality)

**何を見るか**: ユーザーが迷わずにタスクを完了できるか。

| スコア | 基準 |
|--------|------|
| 9-10 | ユーザーテスト不要なほど直感的。認知負荷が最小限 |
| 7-8 | 主要なフローがスムーズ。CTA が明確 |
| 5-6 | 使えるが、一部で迷いが生じる |
| 3-4 | 重要な情報が見つけにくい。ナビゲーションが不明瞭 |
| 1-2 | 操作方法がわからない |

**チェックポイント:**
- CTA（Call to Action）ボタンは目立つか
- ナビゲーション構造は理解しやすいか
- フォームがある場合、ラベルとバリデーションは適切か
- 情報の優先度が視覚的に表現されているか
- ホバー/フォーカス状態のフィードバックがあるか

## Phase 2: QA 評価基準

### 1. 製品の深み (productDepth)

仕様書の要件をどこまで満たしているか。

- 各スプリントで定義された機能が実装されているか
- エッジケース（空リスト、長い文字列、エラー時）は考慮されているか
- データの永続化は正しく動作するか

### 2. 機能性 (functionality)

実際の操作で正しく動作するか。ブラウザ操作で検証。

- ボタンクリック → 期待される動作が起きるか
- フォーム送信 → データが正しく保存されるか
- ページ遷移 → 正しいページに移動するか
- コンソールにエラーが出ていないか

### 3. ビジュアルデザイン (visualDesign)

Phase 1 の4基準のサブセット。プロダクションレベルの見た目か。

### 4. コード品質 (codeQuality)

コードを直接読んで評価。

- コンポーネント分割は適切か
- 命名規則は統一されているか
- エラーハンドリングは適切か
- 不要なコード（デッドコード、console.log）が残っていないか

## 評価の調整方法

閾値やスコアの厳しさを調整するには：

```bash
# 閾値を下げる（通りやすくなる）
npx tsx src/design-loop.ts "プロンプト" 10 6.0

# 閾値を上げる（厳しくなる）
npx tsx src/design-loop.ts "プロンプト" 15 8.0
```

Evaluator のシステムプロンプト（`src/prompts/evaluator.ts`）を直接編集して、採点基準の厳しさを調整することもできる。
